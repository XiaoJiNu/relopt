## 3. 原则（承接结论文档）

1. **一场景一 db**：草坪 db=`064638`；大楼 db=`055425`；query 可同天/跨天。
2. **统一坐标系优先**：相对 GT 与绝对验收共用同一套 pose；目标写到同一 ENU（RTK+杆臂）。
3. **训练相对 vs 验收绝对分开**：Reloc3r loss 要的是相对 R + 平移**方向**；cm/0.2° 绝对指标必须统一真值尺子，不能拿「两次 `/map` 互掐」。
4. **不用公开集**：本方案训练集 **仅 ZC**；公开集仅允许作为对照基线（官方权重零样本），不进 fine-tune 数据混合。
5. **训/测候选同源**：优先 `PAIRSET=M`（MegaLoc 对），与 `eval_zc_sim3` 部署检索一致。
6. **query 奇偶切分、db 不切**：`query_parity=even` 训 / `odd` 测。

### Phase 2：有 RTK → ENU 重写后重制对 / 重训 / 重测

**目标路径（本机已具备 RTK topic + `rtk_gt_*.npz`）**

1. 扩展/新增脚本（建议落 `relopt/scripts/gt_probes/rewrite_pose_enu.py`）：用 `cam_enu` + 朝向（`body_yaw`/`off_rad` + 光轴方位）组装每帧 `T_ENU_cam`，写入旁路目录例如 `data/zc_fix_enu/`、`data/zc_0923_enu/`（**不覆盖**现有 pose，便于回退）。
2. 用 ENU pose **重跑** `regen_pairs_megaloc.py`（基线按 ENU 相对位移过滤）。
3. `ZcRelpose` 指向 ENU 根目录；再跑 Phase 1 同协议 ZC-only 微调。
4. 验收：绝对误差用 ENU GT（`eval_rtk_rescore` 升级为读 ENU pose，或 sim3 直接对 ENU `.pose.txt`）；报告沿/跨航向与角误差。

## 6. 风险与不做什么

| 做 | 不做 |
| :--- | :--- |
| 单场景单 db、MegaLoc 同源对、query 奇偶 | 混 ScanNet / MegaDepth / Co3d 进本方案训练集 |
| Phase1 用 `/map` 训相对并诚实标注尺子 | 宣称跨包/map 已达 cm 或角 &lt;0.2° |
| Phase2 旁路写 ENU pose，可回退 | 覆盖销毁现有 `zc_fix` pose |
| 新 `OUT_DIR` 对照旧 mix50/ftM | 未经批准占满 GPU 长时间训练 |
| 报告分「相对可信 / 绝对待 ENU」 | 把遗忘门槛（公开集）当 ZC-only 硬验收 |

其它风险：

- ZC-only 可能加剧域内过拟合、公开域回退——应用官方权重零样本作参照，而非混训「偷偷」回来。
- `heading_deg` 频率低于 gnss（数百 vs 数千）；朝向 ENU 依赖插值/偏置，Phase2 需做覆盖率与 fix 质量检查。
- `ZcRelpose` 路径与 0923 根目录耦合脆；改动前先跑 1-batch 冒烟。
