# 量产重定位方案：问题分析与优化路线

> 对象：ZC 自研数据上两个量产候选方案——A = Reloc3r + MegaLoc + sim3 预筛（综合排名第 2，135 ms），B = XFeat 稀疏 snap top-4096（第 5，160 ms 墙钟）。
> 目标：A 的角度精度 + B 的平移稳定性，精度再提升，耗时再下降。
> 数据来源：`docs/自研数据复现/自研数据测试topmetric效果_202609291235.md` 归档逐帧误差、本会话新增实测（encoder 分段计时、XFeat 耗时分段、代码审计），全部数字可复算。
> 结论先行：**推荐"级联 + 时序滤波"融合路线**——XFeat 每帧出平移（其强项），Reloc3r(sim3+特征缓存) 低频/按需出旋转（其强项），EKF 时序融合继承 Topometric PF 已验证的角度增益，砍掉 DA3 的 611 ms 重税。预期稳态 ep med <0.3 m / p90 <1 m，eθ med <1.5° / p90 <3°，单帧在线延迟 ~50–80 ms（12–20 Hz）。P0 两项改动（XFeat 旋转组合、Reloc3r encoder 缓存）各自零/近零精度风险，其中 encoder 缓存已实测可把 relpose 段砍 63–66%。

## 1. 原文档两处批注疑问的解答（已核实）

### 疑问 1（L123）：Reloc3r 能否一次推理多对，直接输出多对结果，减少耗时？

**批量意义上已经在做**：`eval_zc_qwen.py:195-199` 把 K 个候选对拼成一个 batch 一次 forward（batch 维 = K），实测 batch=10 摊薄 33.4 ms/对 与 batch=1 的 35 ms/对几乎相同——GPU 在 512×384 分辨率已近算力饱和，"一次喂多对"没有额外可挤。

**但还有 66% 的耗时是纯浪费，可以砍掉**（本会话实测，RTX 5090、amp、K=10）：

| 段 | 实测 | 占比 |
| -- | ---- | ---- |
| K=10 对完整 forward | 334.2 ms（33.4 ms/对） | 100% |
| encoder（两侧 20 图） | 221.2 ms | **66%** |
| 单图 encode（10 图） | 103.4 ms（10.3 ms/图） | — |
| decoder + pose head（残差） | 113.0 ms（11.3 ms/对） | 34% |

原因：Reloc3r 是 CroCo 架构，**encoder 是逐图独立的 ViT 自注意力**（`_encode_image`，无跨图交互），跨图交互只发生在 decoder 的交叉注意力里。当前实现每对都把 query 图重新 encode 一次（K 对 = K 次，浪费 K−1 次），db 图也每次在线重 encode（而 db 图在建图后就固定了）。

**修复 = encoder 特征缓存**（数学恒等，非近似）：
- db 侧：建图时一次性预计算全部 690 帧 encoder 特征并存盘（fp16，768 token×1024 维 ≈ 1.6 MB/帧，全库 ~1.1 GB 显存/磁盘，可接受）；
- query 侧：每帧 encode 一次（10.3 ms），K 对复用。

预期收益（用实测分段折算）：

| 配置 | relpose 段现状 | 缓存后 | 端到端 |
| ---- | -------------- | ------ | ------ |
| top-10（bm3 路线） | 334 ms | ~124 ms（10.3 + 113） | 371 → ~161 ms |
| sim3（K=3） | 97 ms | **~44 ms**（10.3 + 34） | **135 → ~82 ms（12 Hz）** |
| sim5 + bm3（K=5，见 §3.2） | ~160 ms | ~67 ms（10.3 + 57） | ~105 ms（9.5 Hz） |

对照：Topometric 的 DA3 做不到同样的事——DA3 是 10 图**联合**注意力，图像在 encoder 内互为参照，特征不可拆缓存，这是两条路线的架构差异，也是 Reloc3r 系更值得继续投入的原因。

实现量：~40 行（forward 拆成 encode/decode 两调用 + 缓存字典 + 建图导出脚本）；官方 `Reloc3rVisloc` 无此功能，需自写但只动推理入口不动模型。**验证门槛：缓存路径与完整 forward 对同一批数据输出逐位一致（allclose），再跑全量 eval 对齐归档 res_*.npz。**

### 疑问 2（L180）：对照表精度为什么和综合排名总表相差这么多？

**不差——综合表就是对照表三场景列的等权平均，逐行逐列核实一致。** 本会话用两表的公开数字程序化复算：综合表每格 = 对照表（同天、跨天、0923）三格的算术平均，10 个模型 × 6 个统计列（ep/eθ 的 mean/med/p90）**全部 digit-for-digit 吻合**（误差 <0.015，即舍入位）。

看起来"相差多"的两个来源：
1. **平均压缩了场景差异**：如 Reloc3r+MegaLoc+bm3 综合 ep mean 0.63，对照表三场景是 0.79/0.75/0.36——0923 的 0.36 把均值拉低；Topometric PF 的 eθ p90 综合 8.93 = (16.6+7.8+2.4)/3，同天瞬态 16.6 被摊薄。
2. **p90 列是"三场景 p90 的平均"，不是全帧池化 p90**：两表口径如此约定，做跨表比较时不能把综合表 p90 当池化分位数用。

无数据矛盾，无需修表。（本节复算脚本逻辑与 §4 P0-1 一并归档。）

## 2. 两个候选方案的现状问题清单

### 方案 A：Reloc3r + MegaLoc + sim3 预筛（135 ms）

| # | 问题 | 证据 | 严重度 |
| - | ---- | ---- | ------ |
| A1 | 同天 ep p90 1.66 m，比 bm3 的 1.15 m 差：top-3 相似度预筛无位姿投票兜底，look-alike 帧混入即翻车 | sim3 段实测；bm3 行对照 | 高（尾部） |
| A2 | relpose 尺度自由 → 误差集中在 along-track（顺轨向）：p90 4.4 m vs cross-track 0.47 m（无过滤 top-10 审计），任何候选过滤都不改变该比例 | reloc3r 沿轨分解审计（alongcross.py） | 高（架构性） |

### 方案 B：XFeat 稀疏 snap top-4096（160 ms 墙钟）

| # | 问题 | 证据 | 严重度 |
| - | ---- | ---- | ------ |
| B1 | **旋转尾部差 3×**：eθ p90 7.95°（同天 11.1°）vs Reloc3r 系 2.6°。根因两层：(a) snap 口径下 query 朝向 = db 帧朝向（量化到 db 视角间隔）；(b) 近重复 db 帧（帧距 0.57 m）内点最多者常是几乎同一时刻的帧，光线方向近重合，look-alike 翻转直接落 10°+ | 综合表读法段；代码审计证实 (a)：`eval_zc_xfeat.py:117` 把 `recoverPose` 已解出的相对旋转 R **丢弃**（`_, t, ninl = tv`），只用 db heading | **高（但修复近零成本，见 §3.1）** |
| B2 | 160 ms 是 eval 墙钟（含 10 张 db 图 imread + pose loadtxt）；模型侧真实成本 = query extract 8.4 ms + match 2.6 ms×10 ≈ **35 ms**，在线（db 特征预计算后）实际 ~40–60 ms。表面耗时高估 3× | outputs/zc_xfeat_*.json 分段计时 | 中（口径问题，利好） |
| B3 | 平移有 db 帧距地板：snap med 0.23 m ≈ 最近 db 帧距（0.14–0.21 m 采样地板），单帧无法再降 | MegaLoc snap 评测既有结论同构 | 中 |
| B4 | 三角化聚合在短基线下病态：ls/med 均差于 snap（0.55/0.93 vs 0.23），db 帧距 0.57 m 光线交会角太小 | 本次实测 | 中（已规避：选 snap） |
| B5 | 25° 旋转守卫为保 snap 位置精度强制选近重复帧，反过来锁死了 B1 的视角多样性——位置与朝向的候选选择标准冲突 | `geom()` 守卫链 | 中 |
| B6 | 无时序：同 A6 | 架构 | 中 |

**共性根因**（两方案都逃不掉的两条）：
- 单帧方法的位置地板 = db 采样密度（0.57 m 帧距 → med ~0.2 m 就到顶）；
- 尾部（p90/mean）的稀发大错 = 检索/几何模态歧义（look-alike、±180° 走廊），**任何单帧过滤器都只能压不能除，唯一已验证的修法是时序融合**（Topometric PF gate3 把跨天 p90 36→2.8 m 就是证明，代价只是 DA3 太贵）。

## 3. 优化方向（按"改什么 → 预期收益 → 成本 → 验证"给出）

### 3.1 XFeat 旋转修复（修 B1/B5，零推理成本档）

**(a) R 组合——把已算出但被丢弃的相对旋转用起来**：
`geom()` 里 `recoverPose` 已解出 query→db 的 R（当前 line 117 丢弃）。改为 query 朝向 = db 朝向 ⊕ R_rel，snap 输出连续 yaw 而非量化到 db 视角。改动 ~5 行，match 段重跑即可（2.6 ms/对 ×10 对 ×3 场景 ≈ 每场景 <1 min，无需 GPU 重训练）。
预期：消掉朝向量化项（草坪上 p90 的 2–6° 主体）；**不承诺**修 look-alike 翻转（那是模态歧义，归 §3.3 时序管）。短基线下 R 是本质矩阵分解中较良态的分量（病态的是 t 方向），但需实测确认草坪低纹理下的实际增益。
风险：低。若个别帧 R 解退化，ninl<6 守卫已有；可加"R_rel 与恒等偏差 >25° 则回退 db heading"的保险。

**(b) 多候选旋转加权平均**：top-3 候选各自 (db heading + Δyaw_rel) 按内点数圆均值——把 Reloc3r 系"多候选运动平均压旋转噪声"的红利（其 eθ p90 2.6° 的来源）移植到 XFeat 几何上。~10 行，零额外推理（候选已在手）。

**(c) 守卫阈值放宽 sweep**：(a) 生效后 yaw 不再依赖 db 视角一致性，25° 守卫可放宽到 35–45° 换取更大交会角（顺带缓解 B4/B5），对 ep 的影响用 dump 的候选离线扫（零推理，模式同 `audit6_sweep_basemax.py`）。

**(d) top_k sweep（顺手）**：中位匹配数 1255–1630，top_k=4096 可能过量；2048 档预计 extract/match 减半（8.4→~5、2.6→~1.5 ms/对）而内点数仍远超 RANSAC 所需。零成本实验，精度持平即赚 ~15 ms。

### 3.2 Reloc3r 减税加深（修 A4/A5，接疑问 1）

**(a) encoder 特征缓存**（§1 疑问 1 已实测）：sim3 端到端 135 → ~82 ms（12 Hz）；数学恒等，验证门槛 = 输出逐位一致 + 全量 eval 对齐归档。

**(b) sim5 + bm3 叠加**（文档已留口"未测"）：top-5 相似度预筛 + base-max3 位姿投票兜底——用 bm3 修 A1（sim3 同天 p90 1.66 的无兜底问题），用预筛保速度。K=5 + 缓存后 relpose ~67 ms，端到端 ~105 ms（9.5 Hz）。预期精度回到 bm3 行水平（ep p90 ~1.15）而耗时低于 bm3 行的 371 ms 的 30%。若 P0 先做缓存，此项只是 `eval_zc_sim3.py` 改 K=5 + 打开 base_max 聚合，~20 行。

**(c) MegaLoc 描述子 37 ms 的替代**（修 A5，优先级低）：TRAIL 已证明 MegaLoc dg@224 特征可复用于 CRF 仅 1.2 ms 聚合；描述子本身若成瓶颈，可试 224 分辨率档或 INT8——但 37 ms 在 82 ms 端到端里占 45%，值得做，只是放 P2（改分辨率需重新验证检索 hit@2m ≥99% 不退化）。

### 3.3 时序融合（修 A2/A3/B3/B6 + 继承 Topometric 角度红利——**本方案的核心增量**）

已被本仓库验证的三个事实拼起来就是路线：
1. Topometric PF 的时序融合把 eθ med 压到 1.34°（全场最佳）、gate3 把跨天 ep p90 从 36 压到 2.8 m——**时序有效**；
2. PF 贵不在滤波（粒子传播+似然+重采样仅 1.6 ms）而在 DA3 度量观测（611 ms，且联合注意力不可缓存）——**贵的是观测源，不是滤波器**；
3. XFeat（平移 p90 0.59 全场最佳）与 Reloc3r+sim3（旋转 p90 2.65 全场最佳）两个观测源都比 DA3 便宜一个量级且各守一项强项。

**方案：EKF/滑窗滤波器，状态 (x, y, yaw)**：
- 平移观测：XFeat snap（每帧，~40 ms 档）；
- 旋转观测：Reloc3r sim3+缓存（每帧 ~82 ms 或按需/降频触发，如 XFeat 旋转守卫报警时）；
- 运动模型：轮式 /odom + IMU（RA 口径白名单内；注意文档既有声明——真实 /odom 溯源未验证，先用 GT 增量+噪声口径做离线原型，上车前补 /odom 漂移形态学检查）；
- 门控：沿用 gate3 判据（观测 vs belief 差 >3 m / >30° 丢弃），已验证是修尾部尖峰的正确姿势；
- along-track 尺度约束：里程计增量正是 A2 的唯一解（"only temporal/odometry scale fixes along-track"——既有审计结论），EKF 的运动模型天然提供。

**原型零 GPU 成本**：三路观测的逐帧误差全部已归档或可廉价补档（Reloc3r sim3 `res_*_sim3.npz` 有逐帧 pred/GT；XFeat json 只有聚合统计，**需给 eval_zc_xfeat.py 加 --dump 逐帧结果重跑一遍，~1 min/场景**），离线跑 EKF 重算六列统计即可知道融合收益，不动任何模型。

预期（以归档数据为界的合理外推，需原型证实）：ep med ~0.2–0.3（XFeat 单帧 0.23 + 滤波平滑）、ep p90 <1（gate 化尾部）、eθ med ~1.0–1.5（Reloc3r 观测 1.46 + 滤波平均，对标 PF 的 1.34）、eθ p90 <3。稳态口径下同时优于现有全部 12 行。

### 3.4 精度进一步提升（数据/地图侧，不动模型)

- **多条件 db 地图**：三包同向闭环（既有 overlay 验证），同向 pass 可直接合并成 pre/post-mowing 双条件库——跨天老化（当前最差场景：跨天 ep mean 全表最高）主要靠 db 侧条件覆盖修，检索 hit 率已经 99%，瓶颈在 look-alike 判别而非召回。
- **db 加密**：位置地板 = db 帧距（B3）。2 Hz→4 Hz 抽帧建库可把 snap med 地板 0.21→~0.1 m，代价是库容与检索比对线性涨（690→1400 帧仍 <2 ms 比对，可忽略）；仅当产品指标要求 med <0.2 m 时才值得。
- **独立 RTK 口径复核**：/map 噪声底 p50 0.39 m——所有 med <0.4 m 的"提升"已在 GT 噪声内，继续刷 med 数字无判读意义；优化验收应盯 p90/mean（尾部）与 eθ，或换 RTK 口径重测（MegaLoc 仓库已有现成 RTK 链脚本）。
